# 协作答题区

`src/config/features.ts` 中的 `USE_COLLABORATIVE_GUESS_INPUT` 默认是 `true`。改为 `false` 后重新构建，即恢复原有下拉选择、手动发送建议的答题区。此开关不进入房间设置或浏览器偏好。

新版保持每条线索一行，四个编号同时显示选择入口与队员姓名。字号设置仅放大线索，编号和姓名维持标准大小。姓名标签紧凑包裹文字，过长姓名省略截断；空间不足时统一显示首字，仍不足时显示部分首字与总人数（包含已显示的人），悬停只显示完整姓名名单，自己的昵称后加「（我）」，不显示编号、提交者身份或答案状态；无人选择时不显示悬停提示。自己的「我」标签优先展示，其次是提交者，再按座位排序。粗框表示提交者的待提交答案，自己的选择通过编号前的单选圆点识别，点击后立即显示队伍色圆心，并保留队伍色浅底、队伍色文字的「我」标签作为姓名信息，提交者姓名与其他队友统一使用普通浅灰标签，选项格子不增加底色，两种状态可以分别出现。解密阶段加密者不能参与点选，解密者与普通队员可以参与；拦截阶段全队可参与。正式提交仍沿用原有按钮和权限。

## 答题职责提示

身份与阶段标题下方只保留操作指引、权限限制和异常提示。答题负责人看到“由你提交最终答案”，普通队友看到“由「姓名」提交答案”，本轮加密者在解密时看到“本轮仅可查看队友选择”。观战者和已提交队伍不显示常规提示，第一轮跳过拦截、结算和游戏结束也不重复说明。负责人缺失时保留“等待本队解密者／拦截者就位”，强制倒计时到时且尚未提交时显示“时间已到，等待同步”。提交状态统一读取公开的 `submissionProgress`，避免观战者因看不到正式答案而被误判为未提交。不显示提示时移除整行，不保留空段落。

词语分配时，加密者保留「填好 4 个词语后确认」，收到有效反馈请求且尚未反馈或有修改的队友看到「请反馈是否熟悉这些词语」；加密者填写线索时保留「按密码顺序填写 3 条线索」。备用答题界面使用「选择线索对应的词语编号」或「选择编号，提供建议」，同样省略普通等待和已提交提示。

普通队员在按钮区域仍看到静态「等待姓名提交」，仅负责人保留「提交解密答案／提交拦截答案」按钮。右侧按职责显示「选择对应词语编号，提供建议」「选择线索对应的词语编号」或「查看队友选择的词语编号」；粗框说明使用「解密者／拦截者·姓名暂定提交的答案」，本人视角使用「你暂定提交的答案」。只读视角不显示个人单选圆点。姓名过长只截断姓名，悬停可见全名。答题区底部仅在断线、答题结束或已提交时显示状态。

## 临时同步

轮流讨论模式复用同一答题组件和临时同步机制。房间的 `discuss` 阶段根据当前线索所属队伍，分别映射为各队的解密或拦截任务；切换红蓝线索时旧任务失效，权限与提交者跟随新任务更新。流程见 [轮流讨论与阶段提示](./discussion-mode.md)。

- `guess_draft_update` 与 `guess_draft_request` 复用房间 WebSocket，与正式 `action` 通道分离，没有 HTTP 写入兜底。
- `worker/guessDrafts.ts` 仅保存独立的实例内存字段，不进入 `RoomState`、DO Storage、D1、action 幂等日志或 Alarm。接收点选时也不递增正式房间 revision。
- 服务端检查当前任务、玩家身份和权限，只把本队选择发给队员。观战者延续现有双队视角权限，由前端按选中队伍展示。
- 浏览器仅用 `sessionStorage` 保存自己的当前任务选择，包含玩家座位标识与更新时间。任务 key 包含房间、submission ID、阶段、阶段开始时间、队伍和提交者，避免旧轮次、重开游戏、换座后的建议恢复到错误任务。
- DO 首次加载、任务或成员变化时，通过 `guess_draft_state` 请求在线浏览器补发；连接建立或页面刷新后也同步。重复补发不累计人数，较旧的选择不能覆盖较新的选择，清空选择也保留更新时间。
- 同一玩家的多标签页复用现有 BroadcastChannel 主标签页连接。点选、恢复请求与服务端状态均通过主标签页转发，不新增常驻连接或轮询。
- 主标签页在 `pagehide`（刷新、关闭或离开页面）时释放连接与本地主标签页占用记录，并通知其他标签页接管；从浏览器往返缓存恢复时重新选举和请求状态。正常刷新无需等待原有 6 秒租约过期即可接收队友选择。
- 正式提交后清除临时选择并锁定界面；轮次、阶段或游戏改变、玩家离开或换座时清理失效数据。正式答案仍使用原有持久化流程。

DO 休眠不一定使 WebSocket 断线，所以恢复不能仅依赖重连事件。新实例加载正式房间状态后，会向现有连接请求补发。此方案不保证永久保留建议：若 DO 内存已丢失且对应浏览器已关闭，未提交选择无法恢复；在线客户端补发期间也可能短暂显示不完整的建议。

## 验证

`npm test` 覆盖服务端权限过滤、重复及乱序补发、清空选择、阶段/轮次/重开/换座清理、实例重建恢复，以及临时 WebSocket 路径零存储写入。构建检查使用 `npm run build` 与 `npm run worker:typecheck`。
