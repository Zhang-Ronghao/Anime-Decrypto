# 轮流讨论与阶段提示

## 房间设置

大厅「更多设置 → 游戏流程」提供「按阶段进行」和「按线索进行」，位于「胜负规则」之后。新房间和缺少此字段的旧快照默认沿用按阶段进行。只有房主能在大厅修改，开局后锁定；重回大厅保留设置。

- 按阶段进行：双方解密完成后自动进入双方拦截，双方拦截完成后自动结算。
- 按线索进行：第一轮仍各自解密，随后由房主跳过首轮拦截。从第二轮开始，固定先红队线索、再蓝队线索，不交替顺序。
- 讨论红队线索时，红队解密、蓝队拦截；讨论蓝队线索时，蓝队解密、红队拦截。双方都提交才自动切换，提交顺序不限。最后一组完成才统一揭晓密码、判定得分和胜负。
- 结算后仍由房主点击「下一轮」。没有新增房主切换按钮。

「每队讨论」设置每组线索的共用倒计时，默认 2 分钟，可选 1–5 分钟。原来的解密时长用于首轮；首轮跳过拦截仍保留原有规则。关闭强制倒计时时仅提醒；开启时复用原有超时草稿提交和 Alarm 兜底机制，仅填补当前讨论对象缺少的解密、拦截答案，然后自动推进。

## 界面与权限

保持原有布局。顶部显示「讨论红队线索／讨论蓝队线索」，答题区双方看到同样三条线索，各自看到本队的操作职责、暂定答案与建议。右侧进度公开双方是否提交，不公开答案内容。

解密由本队解密者提交，拦截由对方加密／拦截者提交；普通队员只提供建议。当前线索的加密者不能参与本队解密点选，保持只读和聊天禁言。拦截方全队可提供建议。观战者可切换队伍视角，不能提交。

秘密词语、当前密码、未揭晓正确性、对方正式答案和临时建议继续由服务端过滤。已提交的正式答案锁定，不能重复覆盖。

## 状态与临时同步

`RoomRecord` 增加可兼容旧快照的 `discussion_mode`、`discussion_phase_minutes` 和 `discussion_team`，新模式使用房间阶段 `discuss`。共享函数 `guessPhaseForTeam()` 将房间状态映射为各队的 `decode` 或 `intercept` 任务，前端、服务端正式提交与临时建议共用映射。

`RoomSnapshot.submissionProgress` 是从权威状态派生的当前任务提交布尔值，按提交方队伍返回 `{ A, B }`，不包含答案。词语确认、加密、解密、拦截和按线索讨论共用此字段，所有玩家及观战者收到相同进度。界面仅显示队名和沙漏／绿色勾选图标；提交文字仅用于无障碍标签与悬停说明。首轮跳过拦截、结算等无需提交的阶段返回 `null`，显示原有阶段提示。正式答案通过现有 DO Storage / D1 快照路径保存，进度在每次快照时重新计算，刷新或实例重建不会丢失。无需 D1 表结构迁移。

临时建议继续只保存在 DO 实例内存与本人的浏览器会话中，不新增存储写入或轮询。切换讨论对象会改变任务 key，旧点选及迟到补发不能进入新任务。

## 阶段通知

新旧模式共用页面上部中央的短暂浮层，主标题均按玩家队伍显示「开始解密己方线索／开始拦截对方线索」，副标题显示「当前线索：红队／蓝队」。无队伍视角时显示双方职责。提示使用较大的主标题和轻微下移动画，3 秒后自动消失，尊重系统减少动态效果的偏好，不拦截点击、不改变页面布局。

首次加载、刷新不提示；相同阶段的快照、其他人提交、切换观战视角不重复提示。重连收到超过 5 秒的旧阶段不补播。首轮跳过拦截不提示「开始拦截」。

## 验证

`tests/discussion.test.ts` 通过真实 DO HTTP action / snapshot 路径检查权限、顺序、第一轮例外、旧模式、统一结算、经典与生命得分、刷新恢复、公开进度与秘密过滤、超时、设置持久化、任务失效及阶段文案。`npm test`、`npm run build`、`npm run worker:typecheck` 为验证命令。
